# B3 - resize usage menu and keep website downloads current
[Overview](../BASED.md)

Fix retained menu height after provider changes and automate the website's latest download, then publish a patch release.

## Context

The window-style menu retains empty space after disabling providers in Settings. `MenuBarRootView` fixes width but accepts the host's proposed height. The website already links to `/releases/latest/download/AIUsageMonitor.dmg`, but releases publish only a versioned DMG, leaving that URL broken.

## Scope

- Content-driven menu sizing and regression coverage.
- A stable download asset in each release, retaining the existing versioned asset.
- Patch version, release publication, and live download verification.

## Non-goals

- Redesigning the menu, changing Settings presentation, or changing provider/auth behavior.
- Changing signing, supported platforms, or updater behavior.

## Acceptance Criteria

- [ ] Menu content shrinks/grows with provider selection, including zero providers and named OpenAI accounts, despite a previous height proposal. The earlier simplified checks passed, but the user reported the retained native-window height unresolved; continued in [B4](B4.md).
- [x] The website's existing download URL serves the current release DMG and future releases automatically include that asset.
- [x] Tests and release build pass; a new patch release is published.

## Plan

1. Reproduce retained height with a layout regression, then constrain the menu to its ideal vertical size.
2. Publish a stable-name alias of the versioned DMG and document the download contract.
3. Run tests/site build/packaging, bump to 0.1.22, push, and verify GitHub release and live website download.
