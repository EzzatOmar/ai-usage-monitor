# B4 - explicitly resize the menu window after provider toggles
[Overview](../BASED.md)

Resize the actual menu window on every content-size change and publish v0.1.23.

## Context

The user reports that B3/v0.1.22's `.fixedSize` modifier does not fix the retained outer menu height. Rendering the content at its ideal size is not sufficient evidence that the native window has resized. The earlier host tests allowed automatic hosting size constraints, masking a retained-frame failure.

## Scope

- A narrow AppKit sizing bridge scoped to the menu's own native window.
- Regression tests with automatic hosting-window sizing disabled and stale frames deliberately restored.
- Real MenuBarExtra toggle/reopen smoke verification and patch release.

## Non-goals

- Replacing MenuBarExtra or Settings presentation.
- Changing provider authentication, polling, or download publication contracts.

## Acceptance Criteria

- [x] The actual native window shrinks and grows with provider/account rows, even if its host retains the previous frame.
- [x] Reopening after hidden toggles uses the current size, and a restored stale frame is corrected.
- [x] Tests, real-menu smoke checks, and release packaging pass; v0.1.23 is published with a working latest download.

## Plan

1. Add a failing native-window regression that reproduces retained geometry independently of OS-specific SwiftUI sizing behavior.
2. Measure the ideal menu content and explicitly apply its size to its own AppKit window, preserving the top edge and rechecking on window events.
3. Verify repeated on/off toggles and reopen behavior, document the boundary, and publish v0.1.23.
