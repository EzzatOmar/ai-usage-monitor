# S1 - simplify the usage menu
[Overview](../BASED.md)

Reduce the menu to active-provider usage and a single compact footer, removing
configuration controls and disabled-provider placeholders from the routine view.

## Context

The current `MenuBarRootView` iterates over every `ProviderID`, renders a toggle
beside each provider, and keeps disabled providers visible as `Pending`. It also
uses separate rows for refresh and Quit. Task A2 introduces the dedicated home
for those configuration controls.

## Scope

- Filter the main menu and menu-bar quota summary to activated providers.
- Remove provider toggles, credential setup/removal actions, and API-key editors from the main menu.
- Combine last-updated, Settings, icon-only refresh, and Quit actions in one footer row.
- Add focused tests for active-provider selection and quota aggregation.

## Non-goals

- Stop persisting disabled-provider results or alter `UsageStore` polling rules.
- Change provider row quota/error content for activated providers.
- Redesign the separate Settings window created by A2.

## Acceptance Criteria

- [x] The main menu renders only activated providers and shows a useful empty state when none are active.
- [x] Provider rows in the main menu contain no toggles or credential-management buttons.
- [x] Disabled provider results do not affect the percentage in the macOS menu bar title.
- [x] Refresh is an icon-only accessible button on the same footer row as Quit.
- [x] The main menu no longer contains API-key editors or `Check Updates`.

## Plan

1. Add deterministic active-provider selection and enabled-only quota aggregation.
2. Simplify provider rows to status presentation only.
3. Collapse menu actions into one compact footer and provide an empty state.
4. Add unit tests and run full build, test, and package validation.
